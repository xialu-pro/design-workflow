验收说明（使用前必读）

  • 每帧 iframe 为真实视口宽度（1920 / 1440 / 1080 / 740 / 360），卡片内边距、字号、文本行数上限均按该档媒体查询真实生效，非模拟。
  • 架构口径：封面类卡片（cover / full-cover）与图标卡均为「封面区 + 内容区 + 操作区（可选）」三段式，差异只在交互模式——单跳转（整卡即链接、无操作区）与多交互（操作区放 OButton 按钮组）。
  • 卡片宽度按楼层规则：≥601px 四列等分（348px / ≈293.2px / 242px / 157px）；340~600px 按 floor-card.md 禁止四列（内容容器仅 312px，四列只有 69px/卡不可用），取两列平铺、卡宽 150px（card.md 最窄卡宽，文字可用宽 126px）。
  • 容器 padding 按封面位置分方向（单层口径）：vertical 封面在上 → 容器 上/左/右 8、下 0（Body 在下方，底部留白由 Body 下接管）；horizontal 封面在左 → 容器 只留左 8，上/右/下全 0（Body 在右方，右侧留白由 Body 右接管），封面的上/下 8px 内缩由封面自身 margin 承担。⚠️ horizontal 容器上/下不能跟着 vertical 写 8——封面与内容区在垂直方向并排，那 8px 会同时压在内容区上，使「标题→卡顶」「按钮底→卡底」都变成 32 而非 24。因此 horizontal 的「标题/描述 → 卡片 左/右」= 32/24（左侧叠加、右侧直读），与 vertical 的 32/32 不同，见表 3b。
  • ⚠️ 文档内部冲突点 1：Part C「复合卡片交互规格」写"主操作按钮由描边变为 primary1 实心填充"，与「注意事项 · Footer 硬约束」"Footer 按钮必须 OButton medium text（黑字、无底无边框）"矛盾。本页按硬约束以 text 变体实现，请裁决。
  • ⚠️ 文档内部冲突点 2：「颜色 Token 映射」shadow-2 = 0 2px 24px rgba(0,0,0,.15)，与上游 openeuler-token 的 shadow-2（0 6px 18px rgba(0,18,85,.12)，floors/floor-card.md 采用）不一致。本页按 card.md 表现值实现，请裁决。
  • ⚠️ 文档内部冲突点 3（水平布局封面尺寸，2026-10-21 已裁定）：「封面图片规格」表称水平布局图片高度「自适应（跟随卡片高度）」，而「水平布局特殊规则」示例 CSS 为固定宽 + aspect-ratio（高度由比例决定、不随卡片拉伸，且标注为关键约束）。裁定口径：封面既不定宽也不定高——高度 = 内容列高度（文本高度 + Body/Footer padding），宽度 = 高度 × 16/9 反推；与 vertical 互为镜像（vertical 宽铺满→高反推，horizontal 高铺满→宽反推）。窄档回退：列高反推值超过「卡内容宽 − 文字列最小可用宽 160px」时按封顶值收、高度随之按 16:9 缩（601~840 / 340~600 两档触发，≥841 三档不受影响）。⚠️ 纯 CSS 无法落地：grid auto 轨道「列高→封面宽→列宽→列高」是循环依赖，Chrome 只迭代一次不收敛（封面矮 24px 且内容撑爆卡底），故由页面脚本 fitHCovers() 按实测列高回填。请回写规范时一并订正「固定 120px」表述。
  • ⚠️ 文档内部冲突点 4（描述 → 操作区间距）：内边距表给出 Body = 24/24/24/24、又注明「Footer padding 与 Body 同构（上/右/下/左 同值）」，两者叠加会使「描述文字底 → Footer 按钮」= 48px，视觉明显偏宽（直读值表亦未给该项）。本页修正为 24px：带操作区的卡片 Body 下归 0，由 Footer 上内边距单独承担该间距；无操作区的单跳转卡 Body 下保持 24px，作为「描述文字底 → 卡片底」的底部留白。请回写规范时裁决。
  • ✅ 裁定 A（操作区是灵活可选的，2026-10-21）：cover + vertical 与 cover + horizontal 默认无操作区（整卡单跳转）；需要多交互时再把 Footer 加在现有位置（内容区下方 / 右侧列尾部）。Footer 不是必选段，规范应把它标为「可选」而非默认存在。
  • ✅ 裁定 B（≤600px 一律去掉操作区，2026-10-21）：所有类型（cover / icon / full-cover）、两种布局（vertical / horizontal）在 340~600px 档一律不显示 Footer，卡片退化为纯展示。注意 :has(.ocard__footer) 在 footer 被 display:none 时仍然命中，必须显式把 Body 下内边距恢复为该档原值（12px），否则「描述底→卡底」会被压成 0。
  • ✅ 裁定 C（≤840px：cover + horizontal 一排只放一张，2026-10-21）：601~840px 档四列卡宽仅 157px，双列宽 330px 时封面已要 241.8px、文字列被压到极限，故水平卡在该档独占一行。实现要点：flex 行里必须写 flex: 0 0 100%，只写 width: 100% 会被 flex-shrink 收缩回 (676−16)/2 = 330px，两张卡仍并排（已实测踩坑）。floor-card.md 目前只有「≤5 / >5 卡」的列数规则，缺 horizontal 专项规则，需回写。
  • ✅ 裁定 D（≤840px 一律去掉 icon 卡操作区，2026-10-23）：icon 类型在 601~840px 与 340~600px 两档均不显示 Footer（比 cover 的 ≤600px 更严）。同时 icon 从本日起改为按断点分档（原「容器 24/32、间距不分档」口径废止），分档值见表 4a。
  • ✅ 裁定 E（icon 卡间距分档，2026-10-23）：icon 容器 padding 24/24/16/12/12、描述→操作区 16/12/8/无/无、按钮间距 32/32/24、图标槽 32/32/24/24/24；「图标→标题」与「标题区→描述」五档一致（12 / 8）。实现要点：不要用容器统一 flex gap——「标题区→描述」8 与「描述→操作区」16/12/8 两个值不同，统一 gap 会同时作用于 Header→Body 与 Body→Footer 两处、无法分别表达，须分段用 margin 直读。
  • ✅ 裁定 F（full-cover 整卡保持图片比例，2026-10-23）：full-cover 的定义是「卡片内部整个图片填充」，因此整张卡片遵守封面固定比例规则（规则 5）——16:9（默认）或 3:1（超宽形态）；宽度按栅格定（可跨 1~N 列），高度 = 宽度 ÷ 比例（aspect-ratio 反推），禁止内容撑高、禁止写死高度。连带修正：① 内容层（padding 28/24/24 + 标题 ≤2 行 + 描述 ≤3 行）必须在该比例高度内放得下——最窄档跨整行 312px → 16:9 高 175.5px ≥ 内容层 144px（28+32+12+48+24）；② ≤600px 两列平铺档 full-cover 必须跨满整行，单列 150px 只能推出 84px 高、容不下内容层；③ 旧版「full-cover 内容区（界面示意）」节点已移除（第十七轮），高度不再由内容决定。
  • ✅ 裁定 G（full-cover 图标与 Tag 非必选 + Tag 遵循 tag.md，2026-10-23）：full-cover 内容层四类节点中只有标题与正文必选——图标槽非必选、标题后的 Tag 非必选。Tag 本体必须调用 OTag 组件（.otag，规格 / 变体 / 颜色全部遵循 tag.md：本页用 fill × small = 高 20px · 水平内边距 6px · 圆角 4px · tip2 12px），禁止卡片自创徽标样式——旧版 .ocard__badge（高 20px · 圆角 100px · padding 0 8px）的圆角与内边距均不符合 tag.md，已删除；位置为 Head 行内、标题之后（full-cover 整卡即图片，不适用规则 4 中 cover 类型的「右上角 absolute」口径）。三张演示卡分别演示：全要素（图标 + 标题 + Tag）/ 无图标 / 无 Tag。
  • ✅ 裁定 H（Light → Dark 全量 Token 翻转，2026-10-23）：Dark 模式不是"只反色文字"，而是整套 Token 的成对翻转——凡 :root 定义过且本页被引用到的 Token，在 .o-dark 作用域内必须逐项覆盖为 Dark 值：交互态（卡片 hover 标题 primary1、Footer 按钮 hover primary2 / active primary3）、组件自身色（图标槽底色 primary1-light、图标色 primary1、OTag fill 底色 primary1）、阴影全部在内。旧版只覆盖了 fill2/fill3/info1/info3/shadow-2，primary 系列未切换，导致 dark 区 hover 标题用 Light 的 #002FA7 深蓝压在深色卡上（对比度极低、几乎不可见）——本轮已按上游 Token 真源补齐：primary1 → rgb(73,122,248)、primary2 → rgb(42,72,158)、primary3 → rgb(29,51,120)、primary1-light → rgb(18,34,87)。此规则为全局铁律（hard-constraints.md §0.1），适用于所有组件。
  • card.md 未规定、本页取演示值的项（回写规范时需确认）：full-cover Head 行内部间距与标题→正文间距（12px）、水平图标卡结构（图标 + 文字列）、--o-color-primary1-light 取值（8% 品牌色浅底）、Dark 模式 fill3 / 画布底色、深色封面占位色、shadow-1（取上游 token 值）。
  • 社区 Token 口径：openEuler（radius xs/s/m/l 均为 4px，故 full-cover 外档 = 内档 = 4px；openEuler 线上页面另指定 16/8，见 card.md「圆角基准说明」）。
  • Footer 操作按钮引用 OButton 组件：操作区按钮不是卡片自定义样式，而是引用 [components/button.md](../components/button.md) 的「size=medium · Variant=text」组合（card.md Footer 硬约束指定）。卡片只拥有 .ocard__footer 这个布局槽位（flex · 左对齐 · 内边距分档；按钮间距 cover 24 / icon 32→24，均随断点收紧）；按钮本体用组件命名空间 .o-button .o-button--text（SKILL.md L229：组件语义用 o- 前缀），样式独立成块，符合 floor-card.md L19「卡片不写子组件内部样式，仅引用组件规范选尺寸变体」。规格：高 32px · 水平内边距 0（text 变体专属）· 无最小宽度 · 圆角 16px · 字号 font_size-tip1 14px / 行高 line_height-tip1 22px · 无背景无边框 · Enabled 文字色 grey-14。交互：默认 info1 → hover primary2 → active primary3 → 选中 primary1；Disabled 为 grey-14 @ 40%。
  • ⚠️ button.md 内部冲突点 5（text 变体 Disabled 色值）：Token 表（第 161 行）写「grey-14 @ 40%、不使用单独 token」，而交互状态表（第 199 行）写「--o-color-info4」，两者值不同（40% 黑 vs #999）。本页按第 161 行 Token 表实现为 opacity .4，请裁决。
  • 封面占位图标为手写线性 SVG（与 assets/public icons/icon-图片.svg 同语义，占位用途从简）；图标卡图标同为手写线性 SVG（assets 中无功能入口语义图标）。
