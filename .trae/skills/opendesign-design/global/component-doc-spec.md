# 组件文档规范

生成组件设计规范文档（`skills/opendesign-design/components/{name}.md`）时，**必须**将设计稿中的色值、字号、间距等匹配上游 Token 的变量名（数据从 SKILL.md [#数据资源] 中的远端 URL 拉取）：

## 必须匹配的属性

| 属性类型 | Token 格式 | 示例 |
|---|---|---|
| 颜色 | `--o-color-*` | `--o-color-info3`、`--o-color-primary1`、`--o-color-link1` |
| 字号 | `--o-r-font_size-*` | `--o-r-font_size-tip1` (14px) |
| 行高 | `--o-r-line_height-*` | `--o-r-line_height-tip1` (22px) |
| 字重 | `--o-font_weight-*` | `--o-font_weight-regular` (400)、`--o-font_weight-bold` (600) |
| 间距 | `--o-gap-*` / `--o-r-gap-*` | `--o-gap-1` (4px)、`--o-gap-2` (8px) |
| 圆角 | `--o-radius-*` / `--o-radius_control-*` | `--o-radius_control-m`（值随目标社区：openEuler 4px / Ascend 12px） |
| 图标尺寸 | `--o-icon_size-*` | `--o-icon_size-m` (24px) |
| 阴影 | `--o-shadow-*` | `--o-shadow-1` |

> 圆角按 hard-constraints §7.1 分两类落笔：**档位圆角**标注 Token 档位、值注明「随目标社区 Token」（文档中的直值一律视为 openEuler 基准）；**形状语义圆角**（胶囊 100px 等固定造型）直值保留。圆角档位名只有 xs/s/m/l/xl（控件圆角 `--o-radius_control-*` 仅 xs/s/m/l），禁止使用不存在的档位名。

## 颜色 Token 对照表

| 语义 | Token | 用途 |
|---|---|---|
| 一级文字/标题 | `--o-color-info1` | 强调信息 |
| 二级文字/正文 | `--o-color-info2` | 次强调 |
| 三级文字/辅助 | `--o-color-info3` | 辅助信息、面包屑层级 |
| 禁用文字 | `--o-color-info4` | 禁用状态 |
| 链接文字 | `--o-color-link1` | 链接常规状态 |
| 强调色/主色 | `--o-color-primary1` | 当前页面、激活状态 |
| 成功色 | `--o-color-success1` | 成功提示 |
| 告警色 | `--o-color-warning1` | 告警提示 |
| 危险色 | `--o-color-danger1` | 错误/危险提示 |
| 控件边框 | `--o-color-control1` | 输入框边框等 |

## 文档格式要求

样式规范表格中必须包含 Token 列：

```markdown
### 颜色

| 元素 | Token | Dark=off（浅色） | Dark=on（深色） |
|------|-------|-----------------|-----------------|
| 导航层级文字 | `--o-color-info3` | `rgb(var(--o-grey-14) / 0.6)` | `rgb(var(--o-grey-1) / 0.6)` |
```

### 🚨 规格表四条必填要求（缺项即缺规范，实现侧必发散）

写组件规格表（布局 / 内边距 / 图标 / 文字 / 交互态）时，以下四项**必须各占一行（或一节）**，缺任何一项都会导致实现侧「各自看着办」、同一组件在不同变体下视觉分裂：

| # | 必填项 | 反例（缺了会怎样） | 正例 |
|---|-------|------------------|------|
| 1 | **对齐方式**：同一语义元素之间是顶对齐 / 居中 / 底对齐 | OCard「图标规格」表只写尺寸/颜色/背景/圆角，漏写「图标与标题的对齐方式」→ vertical 变体天然顶对齐、horizontal 变体实现侧用了 `align-items: center`，32px 图标对着「标题+描述」整列居中、比标题低约 25px 掉到两者之间 | 「图标与标题**顶对齐**（两种布局一致）」单独一行，并说明为何禁 `center` |
| 2 | **分档表**：凡随断点变化的内边距 / 间距 / 元素尺寸，必须给出 5 档表（≥1681 / 1201~1680 / 841~1200 / 601~840 / 340~600），禁止只给单值 | OCard icon 原写「容器统一 padding top/bottom 24px、left/right 32px，**不分档**」→ 窄卡文字可用宽只剩 102px，而 cover 同档已收紧到 12px，两者严重失衡 | 「容器 padding 24/24/16/12/12」「描述→操作区 16/12/8/无/无」逐档列出 |
| 3 | **跨变体一致性口径**：同一属性在不同变体（如 vertical / horizontal、cover / icon）下是「同值」还是「异值」，必须显式说明 | OCard Footer 按钮间距只有 cover 的 24px，icon 需要 32px 却无规范依据，实现侧只能复用 24px | 「按钮间距 cover 24 / icon 32→24」显式标注哪个变体取哪个值 |
| 4 | **变体结构定义**：每个排列 / 布局变体必须写明 DOM 结构（容器方向、各元素父子关系），且与同类组件的同名变体**镜像** | OCard icon 未定义排列方式结构，实现侧把 vertical 做成「图标与标题横排」，与 cover 的 vertical（封面在上）逻辑相反；还因图标槽（32px）比标题行盒（30/26px）高撑大 header，导致「标题行盒→描述」实测 10/14/8 而非 8 | 「vertical：Header 为 column，图标在上标题在下；horizontal：图标移出 Header 与 Body 并排」+ 可拷贝的 DOM 代码块，并标注与哪个同类组件的哪个变体对应 |

> **为什么要单列这四条**：颜色 / 字号 / 圆角漏了会在视觉上立刻暴露，而对齐方式、分档与变体结构漏了**不会报错、只会悄悄错位**——实现侧会用最顺手的默认值补上，验收时才发现「第三个卡片的图标掉了 / 窄档间距没变」。前三项是 OCard 第十五轮返工的三个直接根因，第四项是第十六轮返工的根因。

> **为什么要加第 4 条**：`vertical` / `horizontal` 是跨组件通用语义（vertical = 视觉主体在文字上方，horizontal = 视觉主体在文字左侧）。结构定义缺失时，实现侧会按个人理解造结构——不仅变体间逻辑相反，还会引发「兄弟元素撑高 → margin 参考点偏移」这类连带几何错误（第十六轮根因）。DOM 代码块写进规范后，生成时照抄即可，无需推断。

### 🚨 结构节点来源规则（区分组件固有结构与业务内容）

从线上页面 / 楼层提炼组件结构时，**必须区分「组件固有节点」与「该页面的业务内容」**：

- **固有节点**：去掉具体文案和图片后依然存在的结构（图标槽、标题、正文、徽标、Footer 按钮等）→ 写进规范
- **业务内容**：该楼层为特定场景加的区块（如 opendesign-home.html「最新上线」楼层给 full-cover 卡加的「界面预览块」 `.oc-card--full-cover__visual`）→ **禁止带入组件规范**

> 反例：OCard full-cover 旧版把楼层的界面预览块写成规范里的「内容区（可选，如界面示意）」节点，导致后续生成时该占位块被反复当作合法结构输出（第十七轮根因）。
> 凡写进规范的「可选」节点，必须自问：删掉它组件是否依然完整成立？若成立，它大概率是业务扩展而非固有结构，要么不写，要么显式标注「业务扩展示例，非组件规范节点」。

> ⚠️ **半透明 Token 写法（强制）**：调色板变量存的是「空格分隔通道值」（如 `--o-grey-14: 0 0 0`），拼接透明度时**只能**用现代斜杠语法 `rgb(var(--o-grey-14) / 0.6)`。
>
> - ✅ 合法：`rgb(var(--o-grey-14) / 0.6)`（空格通道 + 斜杠 alpha，随主题翻转）
> - ✅ 合法：`rgba(0, 0, 0, 0.6)`（写死完整值，逗号分隔）
> - ❌ 非法：`rgba(var(--o-grey-14), 0.6)` —— 展开为 `rgba(0 0 0, 0.6)`，空格通道与逗号 alpha 混用，浏览器整条声明丢弃，会导致描边/阴影/文字色等静默失效。
