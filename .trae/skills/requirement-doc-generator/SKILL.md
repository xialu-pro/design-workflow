# 需求文档生成器（设计师 PRD 助手）

面向华为计算生态产品团队的需求文档助手。适用于没有专职 BA / 产品经理、由设计师兼任需求工作的团队，帮助以规范流程快速产出可评审、可落地的 PRD。

**业务背景**：鲲鹏、昇腾等计算生态产品，以及 openEuler（欧拉）、openGauss（高斯）、openUBMC 等开源项目。文档不涉及市场营销、盈利模式等内容，聚焦功能需求、用户体验与交付协作。文档默认使用中文撰写。

## 安装方式

本 skill 遵循 Agent Skills 开放标准（一个目录 + 一个 SKILL.md），支持 Claude Code、OpenCode、Codex 主流 AI 编程平台。`<SKILL_SOURCE>` 指本 skill 目录（含 SKILL.md 的 `requirement-doc-generator/` 文件夹）。

**项目级安装（推荐，随仓库分发，团队共享）**

```bash
# 在项目根目录执行，按所用平台复制到对应目录
cp -R <SKILL_SOURCE> .claude/skills/    # Claude Code
cp -R <SKILL_SOURCE> .opencode/skills/  # OpenCode 原生
cp -R <SKILL_SOURCE> .agents/skills/    # Codex（OpenCode 亦兼容此路径）
```

**全局安装（本机所有项目生效）**

| 平台 | 全局路径 |
|------|---------|
| Claude Code | `~/.claude/skills/requirement-doc-generator/SKILL.md` |
| OpenCode | `~/.config/opencode/skills/requirement-doc-generator/SKILL.md`（兼容 `~/.claude/skills/`、`~/.agents/skills/`） |
| Codex | `~/.codex/skills/requirement-doc-generator/SKILL.md`（新版亦支持 `~/.agents/skills/`） |

**验证安装**：Claude Code 会话输入 `/` 查看 skills 列表；OpenCode 由 agent 通过原生 skill 工具按需加载；Codex 用 `/skills` 查看，或提示词中 `$requirement-doc-generator` 显式调用。

**注意**：目录名必须与 frontmatter `name` 一致（`requirement-doc-generator`）；修改后未生效时重启对应 CLI。

## 两种 PRD 模式

团队无专职产品经理、设计师兼任需求工作时，需求常由 ISSUE 触发、在与业务对齐中逐步演进——**初始需求清单往往是模糊的**。因此 PRD 分两种模式：

| 模式 | 时机 | 内容 | 适用 |
|------|------|------|------|
| **轻量 PRD**（默认） | 设计前 | 用户、场景、功能项目梳理（带功能编号与优先级）+ 本期不做 | 需求在设计中逐步明晰的常规场景 |
| **详细 PRD** | 二选一：① 设计前直接生成（需求复杂/规则密集时）；② **DEMO 定稿后反向生成**（默认路径） | 完整 7 章结构，第 4 章功能详述从最终 DEMO 提取交互细节与视觉细节 | 复杂需求前置；或 DEMO 定稿后固化需求 |

**轻量 → 详细的演进**：轻量 PRD 与详细 PRD 使用同一文件（`PRD_[主题]_[YYYYMMDD].md`），轻量阶段版本号为 v0.x，DEMO 定稿后反向生成详细 PRD 时升级为 v1.0 并补全 7 章——功能编号（PRD-001…）全程保持不变，确保设计、评审、检视的可溯基准稳定。

**反向生成详细 PRD 的输入**：轻量 PRD + 定稿 DEMO（`design/prototype_*.html`）。从 DEMO 的楼层结构、HTML 交互注释、组件与状态中提取交互细节（操作流、反馈、异常与边界）与视觉细节（布局、组件选型），填入第 4 章"功能需求详述"，其余章节由轻量 PRD 扩展补全。

## 工作流程

### 第 0 步：确定 PRD 模式

AskUserQuestion 询问（无法判断时直接问，禁止替用户拍板）：

> 本需求生成哪种 PRD？
> - **轻量 PRD**（推荐，设计前快速梳理用户/场景/功能清单，DEMO 定稿后再升级详细版）
> - **详细 PRD**（需求复杂或规则密集，设计前就需要完整定义）

DEMO 定稿后反向生成详细 PRD 时，跳过本步与第 1 步提问，直接基于轻量 PRD + 定稿 DEMO 按详细模板升级。

### 第 1 步：交互式提问（必须执行）

使用 AskUserQuestion 工具收集需求要点，规则：

- 每轮不超过 4 个问题，优先提供选项，降低用户输入成本
- 用户回答中出现的新信息即时纳入，避免重复追问
- 必问信息收集齐后立即停止，总计不超过 3 轮
- 若用户一开始就提供了完整信息，可跳过提问直接生成，但需先列出对需求的理解要点请用户确认
- **ISSUE 输入为可选**：需求由 ISSUE 触发时，请用户提供 ISSUE 链接或文本，作为背景与问题定义的素材；无 ISSUE 的需求直接口头/文字描述，不强制

### 第 2 步：生成文档

- 输出为 Markdown 文件；除非用户指定目录，保存到 `docs/` 下，命名为 `PRD_[主题]_[YYYYMMDD].md`，例如 `PRD_部署向导_20260827.md`
- 生成后在对话中给出文档结构摘要与评审建议
- 轻量 PRD 在文档头部状态标注"轻量版 v0.x"；DEMO 定稿后升级详细版时**同名覆盖或同目录更新**，版本号升 v1.0，状态标注"详细版"

## 提问清单

0. **需求来源（可选）**：是否由 ISSUE 触发？有则提供 ISSUE 链接或文本
1. **所属产品与背景**：涉及哪个产品（鲲鹏 / 昇腾 / openEuler / openGauss / openUBMC / 其他），要解决什么问题？
2. **目标用户与核心场景**：谁在什么情况下使用？（常见用户：开发者、运维工程师、生态伙伴、社区贡献者）
3. **功能范围**：核心功能清单及优先级（P0/P1/P2）
4. **设计输入（可选）**：是否已有原型 / 设计稿 / 交互说明可引用
5. **适配与约束（可选）**：涉及的产品版本、硬件平台、兼容性、依赖系统

**模板使用说明**：

- **来源多样**：需求来源不限于 ISSUE——DEMO 生成 Prompt、业务对齐纪要、口头描述均可，在信息表"需求来源"注明即可
- **交付物性质必问**（有 DEMO 诉求时）：可演示原型与正式上线页面的设计基准不同（前者重排版调性评审、允许占位交互；后者重信息完整与真实数据），1.2 的引注必填其一
- **素材即功能描述**：团队 DEMO 前整理的信息往往是"功能点 + 已确认素材"混合体，直接落进描述列，不强制拆分

## Mermaid 图表使用规范

按需选用，每个文档 2-4 张为宜，不为画图而画图：

| 图类型 | 用途 | 常见位置 |
|--------|------|---------|
| flowchart | 业务流程、操作路径、审批流转 | 功能需求详述 |
| sequenceDiagram | 多角色/系统交互时序（用户-工具-平台-硬件） | 核心链路 |
| stateDiagram-v2 | 任务/工单/版本等状态流转 | 状态类功能 |
| journey | 用户操作旅程与体验曲线 | 体验优化类需求 |

业务流程示例：

```mermaid
flowchart TD
    A[用户提交申请] --> B{系统校验}
    B -- 通过 --> C[进入审批]
    B -- 拒绝 --> D[返回修改]
    C -- 审批通过 --> E[流程结束]
    C -- 审批驳回 --> D
```

## 质量标准

生成文档前自查（两种模式均适用）：

1. **可测试**：详细版每条需求都有明确验收标准，杜绝"高效、友好、优化体验"等模糊表述；轻量版允许验收标准暂缺（DEMO 定稿后升级时补全），但功能描述不得模糊到无法设计
2. **可追溯**：需求编号唯一（PRD-001），轻量版与详细版编号保持一致，便于开发与测试引用
3. **边界完整**：覆盖异常场景与空状态，不只写正常流程（轻量版可延后至升级时覆盖）
4. **指标量化**：目标用数字表达（操作步骤数、耗时、错误率等），避免"显著提升"这类不可度量的说法
5. **范围清晰**：明确"本期不做"的内容，防止范围蔓延
6. **讲 What 不讲 How**：描述需求本身，不规定技术实现方案
7. **反向生成保真**：DEMO 定稿后升级详细版时，第 4 章交互与视觉细节必须忠实于定稿 DEMO（含其中的 HTML 交互注释），禁止凭空虚构 DEMO 中不存在的交互

## 写作语气

客观、简洁、主动语态；每句话只表达一个需求点；能用表格就不用长段落。

## 与其他 skill 的关系

- **design-draft-generator**：下游，读取本 skill 产出的 PRD（轻量或详细）生成设计稿；详细 PRD 先行模式下将原型路径回填到 PRD 第 4 章"交互与原型说明"
- **design-workflow**：编排器，把本 skill（阶段 1）与 design-draft-generator（阶段 2-3）串成端到端流水线（PRD 生成 → 确认门 → 设计稿 → 对抗评审 → DEMO 定稿 → 详细 PRD 升级/回填闭环）；独立使用本 skill 时不经过该编排
